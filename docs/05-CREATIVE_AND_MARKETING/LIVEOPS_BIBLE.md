# 📡 COBLOX LiveOps Bible

> **The Pulse of the Game**
> A Live Service game dies without a structured pulse. This document outlines how we run events, updates, and monetization to ensure long-term engagement without predatory practices.

---

## 1. The Patch Cadence

We follow a strict **2-Week Sprint** cycle for content releases, alternating between major and minor updates to manage developer burnout and maintain player interest.

- **Week 1 (Minor Patch):** Balance tweaks, QoL improvements, bug fixes, and rotating shop cosmetics.
- **Week 2 (Major Patch):** New machines, new biomes, narrative progression, or major system overhauls.

---

## 2. Event Structure

Events should never feel "bolted on." They must integrate with the core lore (e.g., instead of a generic "Halloween Event," we run the "Void Resonance Phenomenon").

### Seasonal Events (Quarterly)
- **Duration:** 3-4 weeks.
- **Mechanics:** Temporary resources spawn in the world. Players must modify their existing factories to process these new materials into limited-time cosmetics or permanent titles.
- **Monetization:** Event-specific Battle Pass (Free and Premium tracks).

### Flash Events (Weekly/Weekend)
- **Duration:** 48-72 hours.
- **Mechanics:** Global community goals (e.g., "Refine 1 Billion Tons of Ignis").
- **Reward:** Global buff for the following week (e.g., +10% movement speed, +5% yield).

---

## 3. The Battle Pass Philosophy

Our Battle Pass ("The Coven Directive") respects the player.
- **No Pay-to-Win:** Premium tracks only contain cosmetics, titles, chat colors, and exclusive UI themes.
- **Permanent Access:** Once purchased, a player can progress the pass at any time, even after the season ends. FOMO (Fear Of Missing Out) drives short-term spikes but damages long-term trust.

---

## 4. In-Game Communication

### 4.1 Update Banners & Patch Notes
- Displayed only on the first login after an update.
- Must include a tl;dr summary (max 3 bullet points) and a button to view full notes.

### 4.2 Push Messaging / Server Announcements
- Used sparingly. Only for server restarts, flash event starts, or critical economy exploits.
- Color: System/Warning Red for restarts. Brand Cyan for events.

### 4.3 Countdowns
- Diegetic countdowns are preferred. (e.g., A giant holographic clock on the Sanctum Ruins counting down to a live event, rather than a 2D UI element glued to the top of the screen).
